# 06 - Kernel modules (vendor and ODM dlkm)

[中文版](06-kernel-modules.zh-CN.md)

## Summary

The kernel-modules group is 306 files in two read-only ext4 images: vendor_dlkm_a (271 files, 262 modules) and odm_dlkm_a (35 files, 27 modules). The 289 .ko files are 64-bit little-endian AArch64 ELF relocatable objects, all built for kernel 5.10.205-01655-g5c5a360e9c21 (identical vermagic). Each image carries modules.alias, modules.dep, modules.load, modules.softdep, a build.prop, a NOTICE.xml.gz (empty licence list) and two empty fs_config lists; vendor_dlkm_a also carries modules.blocklist. fstab.eureka mounts the images at /vendor_dlkm and /odm_dlkm, and /vendor/lib/modules and /odm/lib/modules are symlinks into them. Loading is done by /vendor/bin/init.insmod.sh, which reads init.insmod.charger.cfg (charger class, 37 named modprobe entries) or init.insmod.cfg (boot, modprobe -b * against both modules.load files). init.anorak.rc additionally loads wlan and sched-walt directly with modprobe. Module families visible from modinfo and aliases: Qualcomm SoC platform drivers (clocks, interconnect, SMMU, GLINK/QRTR transports, KGSL graphics, MSM DRM, cfg80211/mac80211 WLAN stack, WCD/LPASS audio codecs, SPMI PMIC, UFS) in vendor_dlkm_a, and device drivers for Oculus/Meta peripherals (USB VDM, syncboss, sensors, regulators, charging dock) in odm_dlkm_a.

The role table has one row for each of the 306 files in this group (278 verified, 0 observed, 27 inferred, 1 unverified). It is at `data/subsystems/kernel-modules/roles.tsv`.

## Verified claims

- **K01** (verified): The group has 306 rows: 289 .ko modules and 17 other files. 271 rows are in vendor_dlkm_a and 35 in odm_dlkm_a.
- **K02** (verified): All 289 .ko files are ELF64 little-endian AArch64 relocatable objects (e_machine 183, e_type REL), not stripped, with intree=Y and the same vermagic string.
- **K03** (verified): 261 of the 289 modules carry a modinfo description string; 28 do not (listed with inferred or unverified roles in roles.tsv).
- **K04** (verified): Load and dependency lists are complete and consistent with the .ko files in both trees: every .ko is in modules.load, and modules.dep has one line per module (262 vendor, 27 odm).
- **K05** (verified): fstab.eureka mounts vendor_dlkm at /vendor_dlkm and odm_dlkm at /odm_dlkm, both as read-only ext4 with AVB, logical and first_stage_mount flags.
- **K06** (verified): /vendor/lib/modules and /odm/lib/modules are symbolic links to /vendor_dlkm/lib/modules and /odm_dlkm/lib/modules.
- **K07** (verified): init.insmod.sh reads a config file of action|argument lines. For modprobe it builds the argument list from both modules.load files when the argument is '-b *', and it runs modprobe with both module directories as -d paths. It sets vendor.all.modules.ready and vendor.all.devices.ready at the end.
- **K10** (verified): init.anorak.rc defines two oneshot services that run init.insmod.sh with the two configs. insmod_charger_sh runs in class charger, started by 'on charger'. insmod_sh is disabled and is started by 'on init && property:vendor.skip.init=0'.
- **K11** (verified): init.anorak.rc calls modprobe directly for two modules, both as u:r:vendor_modprobe:s0 with exec_background: wlan with country_code=0 in 'on boot', and sched-walt in 'on boot && property:vendor.scheduler.schedutil=false'.
- **K12** (verified): vendor_dlkm_a modules.blocklist has 69 blocklist lines naming 68 unique modules. Four blocklisted names match .ko files in the module trees: llcc_perfmon, sched-walt, usbip-vudc and wlan.
- **K13** (inferred): wlan and sched-walt appear in vendor modules.load (lines 189 and 216), so the modprobe -b * path from init.insmod.cfg would consider them. init.anorak.rc loads both by name without -b. Behaviour follows the usual modprobe -b convention; modprobe itself was not run.
- **K14** (verified): SELinux defines a vendor_modprobe domain. init may transition to it, and it may read proc_modules. vendor_file_contexts labels /vendor/bin/init.insmod.sh as init-insmod-sh_exec.
- **K15** (verified): The platform file contexts label /vendor_dlkm and /odm_dlkm (and their vendor/ prefixed forms) as vendor_file. No vendor file-context entry names the module directories or the dlkm mount points.
- **K17** (verified): wlan.ko (vendor): WLAN host device driver, Dual BSD/GPL, staging, direct depends on cnss2, cfg80211, cnss_prealloc, cnss_nl and cnss_utils. It has six module parameters, including country_code (charp), which init sets to 0. It defines no exported symbols and imports 503 global undefined symbols. Its transitive dependency closure in modules.dep has 22 entries.
- **K18** (verified): cfg80211.ko (vendor): wireless configuration support, GPL, no module dependencies. It has three parameters, declares firmware files regulatory.db and regulatory.db.p7s, aliases the NETLINK family nl80211, and exports 129 symbols. wlan.ko and mac80211.ko depend on it.
- **K19** (verified): mac80211.ko (vendor): IEEE 802.11 subsystem, GPL, depends on cfg80211 only. It has six parameters (ieee80211_default_rc_algo charp, max_nullfunc_tries, max_probe_tries, beacon_loss_count, probe_wait_ms int, minstrel_vht_only bool), exports 119 symbols and imports 312.
- **K24** (verified): sched-walt.ko (vendor): module name sched_walt, GPL v2, depends on qcom-cpufreq-hw, exports 7 core-control and WALT symbols, imports 261. It has no description string, is in the blocklist (line 46), and is loaded by init.anorak.rc on boot when vendor.scheduler.schedutil is false.
- **K25** (verified): qcom_ramdump.ko (vendor): 'Qualcomm Technologies, Inc. Ramdump driver', GPL v2, no dependencies, one int parameter enable_dump_collection, six exported symbols and 34 imported symbols. init.anorak.rc writes the parameter from persist.vendor.ssr.enable_ramdump.
- **K26** (verified): usbvdm.ko (odm): 'Meta USB VDM abstraction library', GPL v2, staging, no dependencies. It exports 14 symbols (usbvdm_register, usbvdm_subscribe, usbvdm_engine_vdm, usbvdm_subscriber_vdm and others) and is the dependency of five odm modules: pdfu_initiator, usbvdm-glink, external_battery, usbvdm-cypd and charging_dock. init.insmod.charger.cfg loads it with usbvdm-cypd.ko and usbvdm-glink.ko.
- **K27** (verified): modules.dep is depmod output: one line per module, '<absolute path>: <space-separated transitive dependency paths>', with an empty list for a module without dependencies. Vendor paths use /vendor/lib/modules and odm paths use /odm/lib/modules, the symlink names.
- **K28** (verified): modules.alias is kmod alias output with a comment header and 'alias <key> <module>' lines. Keys are OF compatible strings (alias of:N*T*C<compatible> with a C* wildcard line), platform:, i2c:, MHI or NETLINK forms. The vendor file has 841 lines including the header; the odm file has 27 alias lines.
- **K30** (verified): modules.softdep holds softdep rules in the form 'softdep <module> pre: <modules> [post: <modules>]'. The vendor file has 16 rules; the odm file has only a comment header and no rules. Example: softdep msm_kgsl pre: arm_smmu nvmem_qfprom.
- **K31** (verified): Both etc/build.prop files identify the same build: device eureka, Oculus brand, model 'Quest 3', Android release 12 (SDK 32), build id SQ3A.220605.009.A1, userdebug/test-keys, dated Tue Nov 19 17:09:18 PST 2024. Each sets persist.sys.usb.config=none.
- **K32** (verified): The fs_config_dirs and fs_config_files files in both images are zero bytes. Both NOTICE.xml.gz files are 75 bytes and decompress to an XML document with an empty licenses element.
- **K33** (verified): roles.tsv holds 306 data rows (plus a header) with one row per input row and unique partition/path keys. Confidence labels: 278 verified, 27 inferred, 1 unverified (blu_fw_driver.ko).
- **K34** (inferred): The 289 modules fall into two groups. vendor_dlkm_a holds Qualcomm SoC platform drivers (clocks, interconnect, SMMU, GLINK/QRTR transports, KGSL, MSM DRM, cfg80211/mac80211 WLAN, WCD/LPASS audio, SPMI PMIC, UFS). odm_dlkm_a holds device drivers for Meta/Oculus peripherals (USB VDM, syncboss, sensors, regulators). The grouping comes from author strings, descriptions and DT compatibles, not from the device tree.

## Claims with corrected wording

These claims held in substance. The wording below replaces the original.

- **K08** (verified): The two insmod configs use 38 modprobe directives, 4 enable and 4 setprop directives. The 37 named modules in init.insmod.charger.cfg all resolve to a .ko in the two module trees. Only one entry, pmic-glink.ko, differs from its file name (pmic_glink.ko); the other 36 match exactly, so name normalisation is relied on for that single entry.
- **K09** (verified): init.insmod.cfg (boot config) contains one modprobe directive that loads everything, 'modprobe|-b *'. It is followed by setprop vendor.all.modules.ready, then enable directives for the ADSP boot, CDSP boot and CVP boot nodes (/sys/devices/virtual/cvp/cvp/boot), and finally setprop vendor.all.devices.ready.
- **K16** (verified): init.anorak.rc writes to sysfs paths that belong to modules: /sys/module/drm/parameters/vblankoffdelay (line 124), which no module in the two dlkm trees declares, so it is not msm_drm.ko; attributing it to the drm core is inferred (no drm.ko in the module trees). It also writes /sys/module/qcom_ramdump/parameters/enable_dump_collection (lines 403 and 409), which matches the enable_dump_collection parameter of qcom_ramdump.ko.
- **K20** (verified): msm_kgsl.ko (vendor): '3D Graphics driver', GPL v2. Direct depends are nine modules (qcom_iommu_util, qcom-scm, cmd-db, llcc-qcom, clk-qcom, log_gpu_error, mdt_loader, secure_buffer, mem_buf_dev). It has soft dependency pre arm_smmu nvmem_qfprom, matches the DT compatible qcom,kgsl-3d0, exports 6 symbols and imports 506. Its transitive modules.dep closure has 14 entries. powerhint.cfg (outside init and SELinux) is a TOML configuration applied by the power HAL; it lists kgsl-3d0 devfreq nodes and values (for example devfreq/max_freq = 690000000 at line 177), but the writes themselves are performed by the consumer, not by this file.
- **K21** (verified): msm_drm.ko (vendor): two description strings ('MSM DRM Driver' and 'MSM SMMU driver'), GPL and GPL v2 licence tags, author Rob Clark. It has 13 direct depends, soft dependency pre msm-mmrm, seven parameters (including dsi_display0, dsi_display1, modeset, vram), 16 modules.alias lines that map the mdp4, mdss, sde-kms, smmu_sde_unsec, smmu_sde_sec, smmu_sde_nrt_unsec, smmu_sde_nrt_sec and msm-hdcp DT compatibles to msm_drm (each as an exact and a C* wildcard form), 41 exported symbols and 701 imported symbols. Its transitive modules.dep closure has 31 entries. It is loaded by init.insmod.charger.cfg.
- **K22** (verified): qcom_glink.ko (vendor): 'Qualcomm GLINK driver', GPL v2, no dependencies, exports 8 symbols (qcom_glink_native_probe, qcom_glink_native_start, glink_native_pm_ops and others) and imports 91. It is listed in the modules.dep lines of 53 other vendor modules, for example audio_prm_dlkm.ko.
- **K23** (verified): qrtr.ko (vendor): Qualcomm IPC-router driver with a nameserver description, GPL v2 and Dual BSD/GPL tags, and no dependencies. It is the net protocol family 42 (net-pf-42) and exports 8 symbols (qrtr_endpoint_register, qrtr_ns_init, qrtr_get_service_id and others). qmi_helpers.ko has soft dependency pre qrtr. init.anorak.rc defines the service vendor.qrtr-ns (line 324, class core, user and group vendor_qrtr, NET_BIND_SERVICE) with no explicit start line, so it runs as a class-core service; it runs as user vendor_qrtr.
- **K29** (verified): modules.load is a plain list of .ko file names, one per line, with no paths and no options. Vendor has 262 entries and odm has 27, and both lists are the full module sets (K04). The vendor list precedes the odm list in the argument built for the -b * path; whether order changes load order is inferred and was not tested. The first vendor entries are lzo-rle.ko, lzo.ko, qti-regmap-debugfs.ko, regmap-spmi.ko and zram.ko. The first odm entry is as5510.ko.

## Gaps

- Runtime behaviour of the modules (probe functions, device nodes created, effective parameter values after boot) was not determined; all findings are static.
- The modprobe binary (vendor_a/bin/modprobe) was not inspected, so the blocklist and -b behaviour in K13 is inferred, not reproduced.
- Device-tree nodes matching the of: alias keys live in device-tree blobs outside this group and were not resolved.
- Firmware files named by modules (cfg80211 regulatory.db and regulatory.db.p7s, WLAN firmware via wlan_firmware_service) were not located in the mounted partitions.
- Roles for 27 modules come from name, alias or exported symbol names only; blu_fw_driver.ko is unverified; bcl_pmic5, bcl_soc, icc-test, qcom_iommu_debug, qti_qmi_sensor_v2, rimps_log and ddr_cdev have no content-based confirmation.
- Cross-module symbol resolution (which module provides each undefined symbol) was not computed; only per-module export and import counts were produced.
- Deep dives cover 10 modules and 4 configuration or list files (modules.dep, modules.alias, modules.blocklist, modules.load) plus init and SELinux references; the other 279 modules were classified from modinfo, alias or export strings only.
- Module parameter descriptions were extracted for modules with parm entries only; parameter defaults are not in the modules.
- The kernel image and CONFIG_ options are not in this group, so the build configuration of 5.10.205-01655-g5c5a360e9c21 was not checked.
- init.insmod.sh (vendor_a/bin) and init.anorak.rc belong to other subsystems and were cited only for module-loading references.
- References to module-provided nodes in other configuration files (ueventd.rc kgsl and wcd nodes, powerhint.cfg sched_walt and kgsl paths) were located but not analysed in full.
