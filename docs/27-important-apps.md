The set was chosen by hand from the 5,685-entry inventory (`data/inventory/files.tsv`) to cover the user-facing and system functions. The facts in each section come from the manifest and the dex files. Role lines are readings of class and component names; any line that goes beyond the manifest is marked inferred.

The facts for each application are in `data/apks/<name>.json`, and the summary table is `data/apks/summary.tsv`. The page is generated from those files by `tools/apk/gen_apps_doc.py`.

## Method and limits

- Permissions: the sensitive subset is a fixed rule, not a judgement. It is the set of Android runtime (dangerous) permissions, the special-access permissions (MANAGE_EXTERNAL_STORAGE, SYSTEM_ALERT_WINDOW, REQUEST_INSTALL_PACKAGES, PACKAGE_USAGE_STATS, WRITE_SETTINGS), names ending in `_PRIVILEGED`, names starting with `COLOCATION_API_`, and a fixed list of privileged names (BLUETOOTH_STACK, CALL_PRIVILEGED, CONTROL_INCALL_EXPERIENCE, COPY_PROTECTED_DATA, MEDIA_CONTENT_CONTROL, MODIFY_PHONE_STATE, WRITE_MEDIA_STORAGE, SPATIAL_MEDIA_PLAYBACK, SET_SPATIAL_MEDIA_LISTENER, FACE_EYE_INTERNAL_API, HYPERSPACE_CALL, ACCESS_CAMERA_DATA, RECORD_AUDIO_BACKGROUND).
- Interface names: only names whose last segment starts with `I`, has an uppercase second letter and contains a lowercase letter (the AIDL naming pattern). All-caps intent constants are excluded.
- Property-like strings are matches in the dex string pool. They show which properties the code can name, not which ones it reads at run time.
- The JSON lists are capped at 200 items. Only the Settings activity list is capped (200 of 282). Its exported count is over the 200 listed.
- Nothing here comes from a running device.
