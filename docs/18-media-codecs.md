# 18 - Media and codecs

[中文版](18-media-codecs.zh-CN.md)

## Summary

The media-codecs group has 163 files: 49 in system_a, 1 in system_ext_a and 113 in vendor_a. The system side holds the Stagefright and Codec2 framework libraries (32-bit and 64-bit), the media.extractor and media service executables, and a Mainline APEX (com.android.media.swcodec, version 319999900) that ships the mediaswcodec service, a Codec2 software plugin set, its own media_codecs.xml, init.rc and seccomp policy. The vendor side holds 29 Codec2 software plugins per bitness (each exporting CreateCodec2Factory), 14 legacy OMX software plugins (createSoftOMXComponent), Qualcomm QC2 layers (libqcodec2_*) including a V4L2 plugin, a Codec2 HIDL server library used by the vendor.qti.media.c2 HAL, a ClearKey MediaCas plugin, and XML/JSON configuration (media_codecs_anorak.xml, media_codecs_performance_anorak.xml, media_profiles_V1_0.xml, media_profiles_anorak.xml, media_anorak/video_system_specs.json). The variant suffix _anorak comes from ro.media.xml_variant.codecs and ro.media.xml_variant.codecs_performance in vendor build.prop. One row, system_ext_a/lib64/libcodecwrapper.so, is a protobuf wrapper for wearable input telemetry and is not a media codec. Several XML includes named by media_codecs_anorak.xml are not present in the mounted partitions.

The role table has one row for each of the 163 files in this group (103 verified, 56 observed, 4 inferred, 0 unverified). It is at `data/subsystems/media-codecs/roles.tsv`.

## Verified claims

- **grp-01** (verified): The group holds 163 rows: 49 in system_a, 1 in system_ext_a and 113 in vendor_a. Every row has kind file.
- **grp-02** (verified): All 163 files exist at MNT/<partition>/<path> with the recorded size and sha256.
- **grp-03** (verified): roles.tsv has one header line and 163 data rows. Its (partition, path) keys match the input exactly. Confidence counts are 103 verified, 56 observed, 4 inferred and 0 unverified.
- **apex-01** (verified): The swcodec Mainline module is an APEX named com.android.media.swcodec, version 319999900. Its payload is an ext2 image with extents.
- **apex-02** (verified): The APEX payload tree contains bin/mediaswcodec, etc/{init.rc, ld.config.txt, media_codecs.xml, seccomp_policy/} and lib64 with 72 libraries, including Codec2 software plugins, libvpx.so, libopus.so and libmedia_codecserviceregistrant.so.
- **apex-03** (verified): The APEX init.rc declares one service, media.swcodec, which runs /apex/com.android.media.swcodec/bin/mediaswcodec with user mediacodec and the task profiles ProcessCapacityHigh and HighPerformance.
- **apex-04** (verified): mediaswcodec is a stripped 64-bit AArch64 PIE that links libmedia_codecserviceregistrant.so and logs 'media swcodec service starting'. It registers the name media.swcodec and reads its seccomp policy from the APEX or vendor path.
- **mediaextractor-01** (verified): /system/bin/mediaextractor is an AArch64 PIE that registers the media.extractor service (MediaExtractorService). It links libmedia.so and libmediaextractorservice.so and calls limitProcessMemory.
- **mediaextractor-02** (observed): mediaextractor is referenced by init, SELinux file, service and domain files. Its seccomp policy is looked up at /apex/com.android.media/etc/seccomp_policy/mediaextractor.policy and /vendor/etc/seccomp_policy/mediaextractor.policy.
- **mediaserver-02** (observed): The mediaserver service names are declared in the platform service contexts. The binary's file context is mediaserver_exec.
- **libstagefright-01** (verified): libstagefright.so (64-bit) is the core Stagefright library. Its exports cover the MediaCodec and ACodec state machines, MediaCodecList, MPEG4Writer, MediaCodecSource and NuMediaExtractor, and it exports 136 AMEDIAFORMAT_KEY_* constants.
- **libstagefright-02** (observed): libstagefright.so references Codec2 and OMX libraries and the media config and profiling file paths. It names /apex/com.android.media/lib64/extractors and loads an optional libmediaformatshaper.so.
- **libcodec2_vndk-01** (verified): libcodec2_vndk.so (system, 64-bit) is the Codec2 VNDK framework. It exports C2 buffer, block and store APIs, a platform store plugin loader (C2PlatformStorePluginLoader) and DMA-heap and ION usage structures.
- **libcodec2_vndk-02** (observed): libcodec2_vndk.so reads the debug.c2.use_dmabufheaps property and selects DMA-heap paths. The system copy also references media.c2.dmabuf.padding, and the vendor copy uses /dev/dma_heap/system and /dev/ion. Its file and property contexts are set by SELinux.
- **libcodec2-01** (verified): The 32-bit and 64-bit libcodec2.so files in system_a are link stubs. They export no dynamic symbols and import only __cxa_finalize from libc.
- **libcodec2_client-01** (verified): libcodec2_client.so (system, 64-bit) is the client wrapper for Codec2 HIDL component stores. Its Codec2Client::CreateFromAllServices and Codec2Client::Component methods cover queue, start, stop, flush, drain, reset, release, output surface and block pool setup.
- **libsfplugin_ccodec-01** (observed): libsfplugin_ccodec.so is the CCodec plugin that connects the stagefright MediaCodec path to Codec2. It takes its config file names from media_codecs.xml, media_codecs_c2.xml, media_codecs_performance.xml, media_codecs_performance_c2.xml and media_codecs_shaping.xml, and it reads from the swcodec APEX etc directory and a formatshaper path.
- **xmlparser-01** (verified): libstagefright_xmlparser.so (64-bit) is the MediaCodecsXmlParser. It is built on expat and parses the media_codecs*.xml grammar: Include, Settings, Decoders, Encoders, MediaCodec, Alias, Limit, Feature, Quirk, Variant, Tuning and Mapping.
- **variant-01** (verified): Vendor build.prop selects the _anorak variant for both codec XML files and the target. SELinux declares the matching variant properties. ro.media.xml_variant.profiles, which selects the media profiles variant, is not set in any mounted build.prop.
- **vendor-xml-01** (verified): vendor_a/etc/media_codecs_anorak.xml is a well-formed Codec2 codec list with 12 decoders (avc, hevc, vp9 and av1, each with plain, low_latency and secure variants) and 4 encoders (avc, hevc, hevc.cq and heic). It includes media_codecs_google_audio.xml and two files that are missing from the mounted partitions.
- **perf-xml-01** (verified): media_codecs_performance_anorak.xml is a Qualcomm overlay. It holds 15 MediaCodec entries, each with update="true", that add measured-frame-rate-<WxH> limits to the Codec2 decoders and encoders.
- **profiles-02** (verified): media_profiles_anorak.xml is a MediaSettings variant with CamcorderProfiles, VideoEditorCap (maxInputFrameWidth) and ExportVideoProfile. Its internal DTD does not declare the cameraId attribute and rejects the quality value 1080p, giving 11 validity errors.
- **profiles-dtd-01** (observed): The standalone media_profiles_V1_0.dtd defines the MediaSettings schema. Its elements are CamcorderProfiles, EncoderProfile (quality, fileFormat, duration), Video (codec, bitRate, width, height, frameRate), Audio (codec, bitRate, sampleRate, channels), ImageEncoding, ImageDecoding (memCap), Camera, EncoderOutputFileFormat, VideoEncoderCap, AudioEncoderCap, VideoDecoderCap and AudioDecoderCap.
- **video-specs-02** (observed): libqcodec2_platform.so builds the path /vendor/etc/media (plus a suffix) and the file name video_system_specs.json. The JSON keys are referenced in the QC2 platform, utils and V4L2 libraries.
- **qc2-v4l2-01** (verified): libqcodec2_v4l2codec.so (vendor, 64-bit) is the QC2 V4L2 codec plugin. It exports QC2Codec_GetPlugin and the QC2V4l2CodecPlugin::getSupportedCodecs entry, and it uses V4L2 and media device nodes.
- **qc2-core-01** (observed): The QC2 base, core, base-codec, hooks and platform libraries form a layered stack. libqcodec2_core.so exports QC2ComponentStoreFactoryGetter. libqcodec2_hooks.so exports QC2ComponentObserver and its default observer, and it links the android.hardware.power HAL at versions 1.0 and 1.1.
- **vendor-hidl-01** (verified): libcodec2_hidl@1.0.so (vendor, 64-bit) is the Codec2 HIDL server implementation for android.hardware.media.c2@1.0. It provides utils::ComponentStore, Component and CachedConfigurable, and it links the vendor Codec2 VNDK and the filter plugin library.
- **vendor-hal-01** (verified): The vendor.qti.media.c2@1.0-service HAL binary is started by init as vendor-qti-media-c2-hal-1-0 under user mediacodec. It registers the Codec2 IComponentStore and gets its store factory from QC2ComponentStoreFactoryGetter. Its seccomp policies are codec2.vendor.base-arm64.policy and codec2.vendor.ext-arm64.policy. The library name it opens with dlopen is not identified.
- **soft-plugins-01** (verified): There are 29 Codec2 software component plugins in each bitness, under lib and lib64, plus libcodec2_soft_common.so. Each plugin exports CreateCodec2Factory and DestroyCodec2Factory and names one c2.android.* component. libcodec2_soft_common.so exports SimpleC2Component and SimpleC2Interface.
- **soft-aacdec-01** (verified): libcodec2_soft_aacdec.so (vendor, 64-bit, 964592 bytes) is the AAC decoder Codec2 software plugin. It exports CreateCodec2Factory and DestroyCodec2Factory and depends on the Codec2 VNDK, the common soft library and the CCodec utilities.
- **legacy-omx-01** (verified): There are 14 legacy OMX software plugins (libstagefright_soft_*.so) in vendor_a/lib. Each exports createSoftOMXComponent. Some report OMX.google.* component names. libstagefright_softomx.so provides the SimpleSoftOMXComponent base, and libstagefright_softomx_plugin.so exports createOMXPlugin.
- **selinux-file-01** (observed): SELinux file contexts assign the codec binaries and libraries their labels. Two entries name paths that do not exist in the mounted partitions: /system/bin/mediaswcodec (the binary ships in the APEX) and /vendor/bin/hw/android.hardware.media.c2@1.0-service-v4l2-64.
- **hwservice-01** (observed): The Codec2 HIDL interfaces are registered as hwservice names with the hal_codec2_hwservice label in both partitions. The platform property media.c2.dmabuf.padding is labelled codec2_config_prop.

## Claims with corrected wording

These claims held in substance. The wording below replaces the original.

- **sysext-01** (verified): system_ext_a/lib64/libcodecwrapper.so is a protobuf-based encode and decode wrapper for wearable input telemetry (IMU, EMG, gesture, battery, device-state and haptics messages in the com::oculus::wearableinputservice namespace), not a media codec. It embeds the protobuf runtime and has no libprotobuf dependency. Its references are WearableInputService.apk, which packages lib/arm64-v8a/libcodecwrapper.so and lib/arm64-v8a/libwis_input_device.so, and two system_ext libraries that link it: libwis_input_device.so (also packaged in the APK) and wis_handlers.so (a standalone system_ext library).
- **apex-05** (verified): The APEX media_codecs.xml lists 9 Codec2 decoders and 6 encoders, all named with the c2.android.* prefix. Fourteen of the 15 carry an OMX.google alias; c2.android.opus.encoder has none. The file has no Include elements.
- **apex-06** (observed): The mediaswcodec seccomp policy is a line-per-entry allow-list. Syscall entries are a name followed by ': 1' or an argument expression. The file also holds one @include directive that pulls in the code_coverage policy. The header notes that ioctl calls are filtered via the SELinux policy.
- **mediaserver-01** (verified): /system/bin/mediaserver is a 32-bit ARM EABI5 PIE. It instantiates MediaPlayerService and ResourceManagerService, configures and joins an HIDL RPC thread pool (configureRpcThreadpool and joinRpcThreadpool), and links android.hardware.media.omx@1.0.so. Its init service is named media.
- **vendor-xml-02** (observed): Each MediaCodec element holds Limit and Feature children; thirteen of the sixteen also hold an Alias child (the three c2.qti.av1.decoder entries have none). Limit names include size, alignment, block-size, block-count, blocks-per-second, bitrate, frame-rate, concurrent-instances, complexity, quality and performance-point-<WxH> (performance points are Limit names, not a separate element). Feature names include adaptive-playback, low-latency, intra-refresh, video-minimum-quality, bitrate-modes and secure-playback, which has required=true in every entry that carries it. The parser strings include rank, supports- and mapping-.
- **profiles-01** (verified): media_profiles_V1_0.xml (vendor) is a MediaSettings document with CamcorderProfiles for cameraId 0 and 1, 25 EncoderProfile entries, 6 ImageEncoding entries, and encoder and decoder caps (2 VideoEncoderCap, 5 AudioEncoderCap, 1 VideoDecoderCap, 1 AudioDecoderCap). Its internal DTD also declares VideoEditorCap and ExportVideoProfile, but the file has no instances of them. Its internal DTD subset gives 61 validity errors; with the subset swapped for a reference to the system DTD copy, validation gives 0 errors.
- **video-specs-01** (verified): media_anorak/video_system_specs.json is a commented JSON file for the Qualcomm codec platform. It has Video.Features (3 booleans), Video.Presets (5 values), and empty QC2CodecPlugins and QC2PreProcessingFilters lists and an empty QC2PostProcessingFilters object. The name QC2PreProcessingFilters also appears once inside a comment block as a multi-stream example (line 56); the live key is at line 60.
- **selinux-type-01** (observed): SELinux declares mediaswcodec (service domain for hal_codec2_server) in the platform policy, and mediacodec (vendor) with an init transition from mediacodec_exec. The platform hal_codec2_client set includes cameraserver, mediaserver and mediaswcodec. The vendor policy places mediacodec in the hal_codec2 and hal_codec2_server sets, so it is a server-side member rather than a client.
- **misc-libs-01** (observed): libstagefright_flacdec.so is a FLAC decoder (FLAC__ symbols) used by the FLAC decoder soft plugins libcodec2_soft_flacdec.so and libstagefright_soft_flacdec.so. libstagefright_enc_common.so provides cmnMem* helpers and is used by the AMR-WB encoder soft plugins libcodec2_soft_amrwbenc.so and libstagefright_soft_amrwbenc.so. libclearkeycasplugin.so is the ClearKey MediaCas plugin (ClearKeyCasPlugin with openSession and processEcm). The DTD and profile loaders are described in the profiles claims.
- **seccomp-01** (observed): The seccomp policy files share one format: one entry per line, either 'name: 1' or 'name: <argument expression>'. The exceptions are @include directives: two each in mediacodec.policy and mediaextractor.policy, and one in the mediaswcodec APEX policy. The Codec2 vendor base and ext policies (codec2.vendor.base-arm64.policy and codec2.vendor.ext-arm64.policy in vendor_a/etc/seccomp_policy) have no directives. mediacodec.policy exists only as a system copy (system_a/system/etc/seccomp_policy); mediaextractor.policy exists as a system copy and inside the com.android.media APEX payload. Neither has a vendor copy.

## Gaps

- Included XML files that the vendor codec list names, media_codecs_c2_audio.xml and media_codecs_google_c2.xml, are not present in any mounted partition, so their codec entries are unknown.
- Files that the stagefright and CCodec libraries name (media_codecs_c2.xml, media_codecs_performance_c2.xml, media_codecs_shaping.xml, system media_codecs.xml, media_profiles.xml) are not present in the mounted partitions. The runtime search order and which copy wins were not determined.
- The media profiles variant selection depends on ro.media.xml_variant.profiles. That property is not set in any mounted build.prop, so whether media_profiles_anorak.xml or media_profiles_V1_0.xml is loaded at runtime is unknown.
- Runtime files /data/misc/media/media_codecs_profiling_results.xml and /data/vendor/media were named by the libraries but are not in the input, so they were not analysed.
- The library name that vendor.qti.media.c2@1.0-service opens with dlopen (the QC2HALService open message) was not identified from strings. Only its NEEDED list and the exported QC2ComponentStoreFactoryGetter name were read.
- Two vendor binaries referenced by init and SELinux, vendor_a/bin/hw/android.hardware.media.omx@1.0-service and vendor_a/bin/hw/vendor.qti.media.c2@1.0-service, are not rows of this group. They were examined only for NEEDED lists and strings.
- system_a/system/apex/com.android.media.capex (2514355 bytes) references mediaextractor.policy and is not a row of this group. It was not analysed.
- The vendor_file_contexts entry for /vendor/bin/hw/android.hardware.media.c2@1.0-service-v4l2-64 has no matching binary in vendor_a, and the plat_file_contexts entry for /system/bin/mediaswcodec has no matching file in system_a. The runtime labelling outcome for these entries was not determined.
- libcodecwrapper.so (system_ext_a/lib64) is a wearable-input protobuf wrapper, not a media codec. Its group membership should be reviewed; it was analysed but not reassigned.
- Exported symbol families for the 32-bit system libraries and most 32-bit vendor libraries were not enumerated. Their roles rely on NEEDED lists, names and the 64-bit counterparts. Their confidence is labelled observed or inferred accordingly.
- The ext2 APEX payload's ld.config.txt (8226 bytes), code_coverage.arm64.policy and crash_dump.arm64.policy were listed but not analysed.
- The mediaswcodec APEX libcodec2_hidl@1.0.so (282944 bytes) differs in size from the vendor copy (283184 bytes). The difference was not analysed.
- ClearKey license protobuf message definitions and the ClearKey session logic were not analysed beyond the exported class and method names.
- Component-level codec capability values in media_codecs_anorak.xml (the limit ranges) were not compared with the performance overlay values or with runtime queries.
