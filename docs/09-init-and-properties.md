# 09 - Init scripts and build properties

[中文版](09-init-and-properties.zh-CN.md)

## Summary

The init-and-properties group covers 183 manifest rows (181 regular files, 2 symlinks) across five partitions (odm_a 24, product_a 2, system_a 80, system_ext_a 31, vendor_a 46). It contains the init executable and its two symlinks, the main system init script with zygote and USB variants, 170 .rc files defining 191 services and 371 on-triggers, vendor init scripts for the anorak SoC and eureka device, three vendor shell helpers, two fstab files, two ueventd.rc rule files, and five build.prop files holding 395 distinct property keys. Boot flow as declared by the files: the init binary reads /system/etc/init/hw/init.rc, which imports /init.environ.rc, the USB scripts, /vendor/etc/init/hw/init.${ro.hardware}.rc (init.eureka.rc, which imports init.anorak.rc) and /system/etc/init/hw/init.${ro.zygote}.rc (init.zygote64_stub32.rc, selected by ro.zygote=zygote64_stub32 in the vendor build.prop). The fstab selected by ro.hardware is /vendor/etc/fstab.eureka, loaded by mount_all in init.anorak.rc. The ro.hardware value itself is not in any build.prop of this group.

The role table has one row for each of the 183 files in this group (178 verified, 5 observed, 0 inferred, 0 unverified). It is at `data/subsystems/init-and-properties/roles.tsv`.

## Verified claims

- **C01** (verified): The group has 183 rows: 181 regular files and 2 symlinks, split odm_a 24, product_a 2, system_a 80, system_ext_a 31, vendor_a 46.
- **C02** (verified): All 181 regular files match their manifest sha256 values; the two symlink rows carry no hash ('-').
- **C03** (verified): The 170 .rc files contain 191 service definitions in 145 files and 371 on-triggers; 23 odm_a, 1 product_a, 76 system_a, 30 system_ext_a, 40 vendor_a rc files.
- **C04** (verified): Text files in the group are LF-terminated with no CR bytes; the only file without a trailing newline is the init binary.
- **C05** (verified): Six service names are each defined in two or more rc files: zygote (4 files), zygote_secondary, surfaceflinger, health-hal-2-1, vendor.audio-hal, vendor.qti.hardware.display.composer (2 files each). 183 distinct service names exist.
- **C06** (verified): The init binary is an aarch64 ELF64 PIE, dynamically linked with interpreter /system/bin/bootstrap/linker64, stripped, 12 program headers and 30 section headers, entry point 0xac000.
- **C07** (verified): The init binary's GNU build ID is ab61af44159984e98f5fa1da776a36db and its Android ident note carries the value 0x20 (32), matching ro.build.version.sdk=32 in the system build.prop.
- **C08** (verified): The init binary lists 20 NEEDED shared libraries, including libselinux.so, libfs_mgr.so, libprocessgroup.so, libcutils.so, liblog.so, libbase.so, libutils.so, libc++.so, libc.so, libm.so and libdl.so.
- **C10** (verified): The init binary embeds the paths it searches: /system/etc/init/hw/init.rc, the per-partition init directories (/product, /system, /system_ext, /vendor, /odm), fstab search prefixes (/system/etc/fstab., /vendor/etc/fstab., /odm/etc/fstab., /first_stage_ramdisk/fstab.), ueventd rule paths (/system/etc/ueventd.rc, /vendor/ueventd.rc, /odm/ueventd.rc, /ueventd.), and the property store paths /dev/__properties__ and /data/property/persistent_properties.
- **C11** (verified): The init binary contains the string ro.hardware and the string ueventd started!, so one binary provides the init role and a ueventd role.

- **C14** (verified): system_a/init is a symlink to /system/bin/init, and system_a/system/bin/ueventd is a symlink to init (relative target).

- **C16** (verified): init.rc contains 51 on-blocks, 6 service definitions (boringssl_self_test32, boringssl_self_test64, boringssl_self_test_apex32, boringssl_self_test_apex64, ueventd, console) and 23 setprop lines. Its early-init block starts ueventd, and late-init triggers the fs, post-fs, post-fs-data and zygote-start stages.
- **C17** (verified): init.zygote64_stub32.rc defines zygote (app_process64, sockets zygote and usap_pool_primary) and zygote_secondary (stub_zygote wrapping app_process32). Class main, priority -20, root user. It is selected by ro.zygote=zygote64_stub32, which vendor build.prop sets.
- **C18** (verified): init.anorak.rc imports four debug, cgroup, power and usb scripts, defines 23 services and 36 on-blocks, and calls mount_all on /vendor/etc/fstab.persist (early) and /vendor/etc/fstab.${ro.hardware} (early and late).

## Gaps

- ro.hardware is not set in any build.prop in this group and is not present in the mounted tree; the eureka selection of init.eureka.rc and fstab.eureka is inferred from file names. Its source (kernel command line or bootloader) was not examined.
- Precedence when the same property key is set in several build.prop files (persist.sys.usb.config, dalvik.vm.heap*, ro.control_privapp_permissions) was not determined; the init loader logic is not in the tree and the binary was not disassembled.
- The built-in command table and the ueventd-versus-init mode selection were checked only by exact-string presence in the init binary; no disassembly or control-flow analysis was done. verity_load_state and rm are absent as standalone strings.
- The init binary's version or build banner string was not identified.
- The first-stage ramdisk init.rc (first_stage_ramdisk) and the boot image were not in this group; only the system and vendor copies were examined.
- Service binaries named by the rc files (under /vendor/bin, /system/bin, /system_ext/bin, /product/bin, /odm/bin) belong to other subsystems and were not inspected; only what the scripts declare is recorded.
- Full text is not covered for the larger scripts: init.rc (55,112 bytes), atrace.rc (24,276), init.anorak.rc (18,409, partly covered), init.anorak.cgroup.rc (9,637), init.anorak.usb.rc (8,663), init.usb.configfs.rc (7,690), wifi.rc (5,715), perfetto.rc (4,858). Their sections list services, triggers, imports and counts only.
- Absent from the mounted tree: /vendor/bin/install-recovery.sh, /system/bin/move_widevine_data.sh, /system/bin/linkerconfig (the bootstrap/linkerconfig variant is present), /odm/etc/ueventd.rc. The .ko modules named in init.insmod.cfg and init.insmod.charger.cfg are not in the group.
- The 2 symlink rows have no sha256 in the manifest; their targets were checked by readlink only.
- The compiled SELinux policy (precompiled_sepolicy in odm_a) was not decoded; SELinux evidence comes from source-form file_contexts, property_contexts and CIL. Labels for the rc files and build.prop files inherit from directory-level rules that were not examined.
- Which duplicate service definition is active at runtime (for example, the four zygote variants, or surfaceflinger and health-hal-2-1 in two files) depends on ro.zygote and ro.hardware values and on the import order; only the zygote selection logic was checked.
- The property semantics (what each build.prop key does at run time) were not checked; the roles describe grouping and content only.
