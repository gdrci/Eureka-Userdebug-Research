# 16 - Power, thermal and charging

[中文版](16-power-thermal-charging.zh-CN.md)

## Summary

The power-thermal-charging group holds 21 files: 3 in product_a, 7 in system_a and 11 in vendor_a. It contains the Android charger-mode binary (AArch64 PIE) with its animation description and two PNG icons; HIDL thermal HAL 1.0 and 2.0 interface libraries in 32-bit and 64-bit system copies and 64-bit vendor copies (the system and vendor 64-bit copies differ only in build-id); the thermal helper library libthermalhalutils.so and its JSON sensor and cooling-device configuration, which the odm perf_service binary links and reads; two TOML power-hint configurations for the power HAL; a charger-class init module list run by init.insmod.sh; the battery-listener library loaded by dlopen from the audio HAL; the external battery client library linked by the health HAL implementation; and the IBatteryStats AIDL library linked by libsensorservice. The server processes for the thermal HAL (odm perf_service) and the external battery HAL (odm vendor.oculus.hardware.externalbattery@1.0-service) sit in odm_a and are outside this group. Deep-dive coverage: 13 items.

Role table: `data/subsystems/power-thermal-charging/roles.tsv` (21 files: 19 verified, 2 observed, 0 inferred, 0 unverified).

## Claims with corrected wording

- **C11** (inferred): The charger has no DT_NEEDED entry for libexternalbattery.so and no .symtab section. It is stripped, but its .gnu_debugdata section holds a compressed symbol table that defines the IExternalBattery proxy and stub classes and the hardware::oculus::health::ExternalBattery wrapper, so the binary contains its own compiled copy of that code rather than loading libexternalbattery.so at run time.
- **C17** (verified): The thermal HAL libraries are linked by 15 files. In odm_a: perf_service (1.0 and 2.0) and wattsup (2.0). In system_a: libandroid_servers.so in lib and lib64 (1.0); libvrsrecorder.so, libvrsrecorder_plugin_temperaturereader.so, libvrsrecorder_utils_camera.so and libvrsrecorder_utils_sensorapishim.so (2.0); and the lib and lib64 copies of android.hardware.thermal@2.0.so (each linking @1.0). In system_ext_a: perfstream, vrdevicemanagerserver and libperfstreamprovider.so (2.0). In vendor_a: the vendor copies of libthermalhalutils.so (1.0 and 2.0) and android.hardware.thermal@2.0.so (@1.0).
- **C25** (verified): Non-table keys are 629 path entries (keys beginning with /), 14 clock-level entries (VR_MODE_* in clocks_cpu and clocks_gpu), 106 priority entries and 9 duration entries.
- **C30** (observed): animation.txt is a directive file with one animation directive (3 cycles, 2 first-frame repeats, file charger/battery_scale), one percent_display directive and 12 frame directives. Each frame directive has a display time (disp_time column) of 750; the file does not state the unit. The six battery-level ranges 0-9, 10-24, 25-49, 50-74, 75-99 and 100-100 are each used by two frames. The charger scans the percent_display line with the pattern c %d %d %d %d %d %n%*s%n and frame lines with frame: %d %d %d.
- **C31** (inferred): The percent_display line is scanned as a literal c followed by five integers (1150, 216, 216, 216, 255) and a font name. The header lists six numeric fields (x, y, r, g, b, a) before the font, so the assignment of the five values to header fields is not established by the file or the charger.
- **C40** (observed): SELinux file-context and hwservice-context files map the thermal HAL server binaries and the external battery service to their own labels, and map the thermal and external battery HIDL services to hwservice labels. The sysfs labels for the thermal tree and the external battery supply are defined in the vendor SELinux policy file.
- **C41** (observed): The vendor property context maps persist.vendor.enable.thermal.genl to vendor_thermal_prop. The consumer is not among the 21 group files; the property name occurs in odm_a/bin/hw/perf_service, and vendor_a/build.prop line 64 sets it to true. Which of these reads it was not determined.

## Gaps

- No disassembly was performed. The charger main loop, the thermal HAL algorithm, the battery-listener threading and the IBatteryStats transaction codes and method list are not determined.
- The config Type values BATTERY, SKIN, CPU, GPU, NPU, USB_PORT and FAN do not appear as literal strings in libthermalhalutils.so or perf_service. SKIN and USB_PORT appear only in framework.jar and services.jar. How the parser maps these config values to enum values is not determined.
- The meaning of the seven threshold slots per sensor is inferred only (C38). The clock units in powerhint.cfg are inferred only (C39).
- The charger command-line option set (its getopt string) was not determined.
- Whether the charger carries a statically linked IExternalBattery proxy is inferred (C11). The binary is stripped and has no symbol table.
- libbatterylistener.so has a DT_NEEDED entry for android.hardware.power@1.2.so, but no undefined symbol in the library refers to android::hardware::power::V1_2::IPower. Its use of the power HAL is not determined.
- The leading c token in the percent_display line is a literal scan token. The mapping of 1150 and the RGBA values to position and colour is inferred from the header comment only (C31).
- battery_scale.png was checked by its header, its tEXt chunk and a visual render. Per-frame pixel content was not decoded.
- The runtime search order for animation resources (product, system and res paths) is known from strings only.
- libthermalhalutils.so embeds the build-time source paths vendor/meta/services/perf/lib/libthermalutils/src/config_parser.cpp and thermal_files.cpp. These are observed strings only against any source tree.
- odm_a/etc/init/vendor.oculus.hardware.externalbattery@1.0-service.rc was listed as containing the external battery service but was not read. The server binary odm_a/bin/hw/vendor.oculus.hardware.externalbattery@1.0-service was not analysed.
- DT_NEEDED consumer lists cover only the mounted partitions (odm_a, odm_dlkm_a, product_a, system_a, system_ext_a, vendor_a, vendor_dlkm_a). Dlopen-based consumers such as the audio HAL were found only by string search.
- The consumer of persist.vendor.enable.thermal.genl (vendor_property_contexts line 30) was not searched for across binaries.
- The roles.tsv file has a header row followed by 21 data rows. Its role descriptions for battery_fail.png and the charger binary are observed rather than verified, because their function is taken from strings and init text.
