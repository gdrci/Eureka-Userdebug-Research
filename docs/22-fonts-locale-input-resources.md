# 22 - Fonts, locale, input and resources

[中文版](22-fonts-locale-input-resources.zh-CN.md)

## Summary

The group holds 448 input rows: 434 in system_a, 8 in odm_a and 6 in product_a. It has three parts. Fonts: 210 system font entries (204 TrueType or OpenType files, two CJK TrueType collections, four symlinks) and six product fonts; system fonts are indexed by system_a/system/etc/fonts.xml (familyset version 23, 157 families, 24 aliases) with Roboto as the default sans-serif face, and product fonts are added through product_a/etc/fonts_customization.xml. Locale data: a tzdata2021a bundle with its tz_version string, 37 hyphenation pattern (.hyb) files, two BMD binary tables read by libFFTEm.so, and a usr/icu symlink into the com.android.i18n APEX. Input configuration: 176 Linux key layout (.kl) files, six key character maps (.kcm) and eight input device configuration (.idc) files, mostly gamepad and remote-control devices plus emulator and VR entries. All 443 regular files match their recorded size and sha256, and the five symlinks resolve.

Role table: `data/subsystems/fonts-locale-input-resources/roles.tsv` (448 files: 258 verified, 187 observed, 3 inferred, 0 unverified).

## Verified claims

- **C02** (verified): Every regular file row is present in the mount with the recorded size and sha256; no row is missing.

## Gaps

- SELinux file contexts for product_a and odm_a are not present in the mount; only system_a/system/etc/selinux/plat_file_contexts and vendor_a/etc/selinux/vendor_file_contexts were found, so labels for the product fonts and for odm paths beyond the vendor pattern are not established.
- The APEX payloads (com.android.i18n apex_payload.img and com.android.tzdata apex_payload.img) were not unpacked; the ICU data files and the active tzdata copy under /apex are not inspected. The system tzdata copy is tzdata2021a; whether the APEX copy is newer is not determined.
- The purpose and file format of the BMD tables (RFFstd_501.bmd, RFFspeed_501.bmd) beyond the size-header relation are not determined, and the functional role of libFFTEm.so (symbol prefixes bts_, bbs_, bbf_, bpi_, btk_SDK_) is not determined. No string reference to RFFspeed_501.bmd was found in the searched binaries.
- The hyphenation (.hyb) format beyond the magic value, the size field at 0x14 and the header words listed in C32 was not decoded; pattern counts and language coverage were not extracted.
- Per-script glyph coverage of the Noto fonts was not computed; only glyph counts (maxp) and name tables were parsed. The fallback order implied by fonts.xml was not simulated.
- Vendor names for the Vendor_<VID>_Product_<PID> key layouts are inferred from general USB ID knowledge and were not checked against a USB ID database; 171 vendor-named files were described from their first comment line, and only a sample was read in full.
- The purpose of AndroidClock.ttf (clock digits) and of DroidSans and DroidSans-Bold (legacy alias names) is inferred from names only; no reference to them was found in fonts.xml, in init, or in the SELinux files.
- The mime labels for AndroidClock.ttf (application/SIMH-tape-data) and for 40 font, hyphen, BMD and tzdata files (application/octet-stream or mis-labelled 'data' types) are input classifications that were corrected only where verified; the input classification was not rewritten.
- The oculus-device.kl and oculus-device.kcm files referenced by the Vendor_2833 IDC belong to the sensors-mcu-meta-hal group; their full behaviour is outside this group.
- The effects of the product fonts_customization.xml at run time (how libandroid.so applies customization families and resolves weights) were not traced; only the configuration contents and the path strings were verified.
- The runtime loading path of the key layout, key character map and IDC files (which process reads /system/usr/keylayout etc.) was not traced; the only static references found are the SELinux labels and the mode of the paths.
