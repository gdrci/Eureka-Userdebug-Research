# 23 - Configuration files

[中文版](23-config-files.zh-CN.md)

## Summary

The config-files group has 392 rows in five partitions: system_a 270, system_ext_a 73, vendor_a 28, odm_a 11, product_a 10 (389 regular files, 3 symlinks). It holds 123 trust-anchor PEM certificates (system_a security/cacerts, each file named by its OpenSSL subject hash), 41 compiled terminfo entries, 37 hyphenation licence texts, five gzipped NOTICE indices, 38 zip-container model archives (.ptl, .pt, .jit), four ExecuTorch program files (.pte, .ff) and three octet-stream .ptl models for body, hand, face, input, object, IoT, passive-tracking, wake-word, depth and audio features, plus runtime configuration read by init, the process-group library, the dynamic linker, the font stack, the camera and audio HALs, the OpenXR loader and the telemetry services. Binary items include two eBPF objects (netd.o, clatd.o), an AArch64 PIE helper (ip-up-vpn), a Cap'n Proto HMD configuration, a binary linker namespace protobuf and an fs_config directory table. Every row's file is present with the recorded sha256. The 15 deep-dive items give format facts, keys and literal or SELinux references found in the mounted image.

Role table: `data/subsystems/config-files/roles.tsv` (392 files: 261 verified, 96 observed, 35 inferred, 0 unverified).

## Gaps

- Two security/cacerts files on system_a (a3896b44.0, a7605362.0) are classified under subsystem gpu, not config-files; they are outside this group and are not in roles.tsv.
- The loader of vendor_a/etc/resourcemanager_anorak_max98388.xml is not identified: no literal path to that file name exists in the vendor binaries or libraries (grep count 0), and libar-pal.so names only usecaseKvManager.xml and card-defs.xml.
- The loader of system/etc/facetracking/runtime/config.json is not identified: libtrackingengines.so holds the directory literal /system/etc/facetracking/runtime but no literal ending in config.json for that path.
- vendor_a/firmware/blu.bin and blu.toml, both named by odm_a/etc/fw_init.cfg, are absent from the mounted image.
- The /apex/com.meta.xr targets of the two odm_a openxr symlinks are absent from the mounted partitions. The system x86_64 manifest points to lib/x86_64/libopenxr_forwardloader.so, but VrDriver.apk has no x86_64 openxr entry, so that library was not found.
- linker.config.pb field semantics (38 entries in field 3, 19 in field 4) are not checked against the Soong linker_config.proto, which is not in the mounts; the labels given are inferred from the library names.
- Not decoded beyond headers or sizes: vendor_a/etc/Diag-CHGPD.cfg, vendor_a/etc/peripheralconfig/pcl_config.bin, vendor_a/etc/acdbdata/anorak_max98388/workspaceFileXml.qwsp, the record layout inside vendor_a/etc/HRTF_KS.hrtf, system/etc/mldepth/stereo_model*.ptl (header bytes TH1), system/etc/scene_objects/mask2former_v5.ptl (header bytes etz0), the Caffe2-style NetDef .pb files under system_ext_a/etc/assistant, and the contents of boot-image.prof and boot-image.bprof beyond their first bytes.
- The 32 zip-container model archives and 6 bodytracking archives were listed by entry name only. producer_info.json, model_version_metadata and the ExecuTorch program contents were not read, and the libraries that load them were not traced.
- threadpolicy.conf is not strict JSON. How vrdevicemanagerserver parses it, and whether it tolerates the trailing comma, was not traced.
- Consumers of cgroups.json, task_profiles.json, fonts.xml, linker.config.pb, fs_config_dirs and the BPF objects were identified from literal strings only. Runtime behaviour was not traced.
- 35 rows are labelled inferred because they rest on file names only: 34 hyphenation licence texts other than the three that were read, and system/etc/seccomp_policy/code_coverage.arm.policy.
- The bpfloader_min_ver and bpfloader_max_ver section bytes were read raw (00000000 and 00000100). Their integer width and endianness were not confirmed.
- SELinux coverage: literal and regex searches covered the file_contexts, property, service and seapp context files in the mounted partitions. Wildcard rules were not enumerated, so context coverage of the non-matching group files is not exhaustive.
- init.insmod.sh (/vendor/bin/init.insmod.sh) and vendor_a/etc/init.insmod.charger.cfg (outside this group) were not inspected.
- Reference searches covered the .rc files, the *contexts* files and literal strings in the mounted bin, lib, lib64 and priv-app directories. Other reference forms, such as defaults compiled into unlisted binaries, may exist.
