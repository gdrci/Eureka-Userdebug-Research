# 17 - Keystore, keymaster and crypto

[中文版](17-security-keystore-crypto.zh-CN.md)

## Summary

The group has 60 classified rows: 56 regular files and 4 symlinks, spread over system_a (40), system_ext_a (1) and vendor_a (19). It covers four layers. (1) The system keystore2 stack: the Rust keystore2 daemon, its AIDL/NDK and C++ stubs, Rust crypto and attestation helpers, the keystore client CLI and the wait_for_keymaster boot helper. (2) Gatekeeper: the gatekeeperd and gatekeeperserver daemons, the gatekeeper core libraries, the OVR gatekeeper service and client libraries, and the Qualcomm gatekeeper 1.0 HAL service and implementation. (3) Keymaster and KeyMint: HIDL 3.0, 4.0 and 4.1 interface libraries in system and vendor, software keymaster libraries, the Qualcomm keymaster 4.1 HAL service and backend, and the qseecomd TEE daemon used by the vendor services. (4) fs-verity and AVB verity: fsverity_init (started from init.rc), set-verity-state with its enable-verity and disable-verity links, libfsverity, and the fs-verity release X.509 certificate. Cross-cutting libraries are BoringSSL libcrypto (32-bit and 64-bit) and the Widevine OEMCrypto libraries. All 56 regular files match their recorded sha256 and size. Binaries are stripped, so behaviour is taken from exported and imported symbols, NEEDED entries, strings, and init and SELinux text files.

The role table has one row for each of the 60 files in this group (40 verified, 11 observed, 9 inferred, 0 unverified). It is at `data/subsystems/security-keystore-crypto/roles.tsv`.

## Verified claims

- **cov-1** (verified): The group has 60 input rows (56 regular files, 4 symlinks). roles.tsv has one row per input row, with the same partition and path set and no duplicates.
- **cov-2** (verified): All 56 regular input files match their recorded sha256 and size.
- **cov-3** (verified): Four rows are symlinks: system_a/system/bin/disable-verity and enable-verity point to set-verity-state; system_a/system/bin/tee points to toybox; vendor_a/bin/tee points to toybox_vendor.
- **ks2-format** (verified): keystore2 is a stripped, dynamically linked AArch64 PIE for Android (ELF64, interpreter /system/bin/linker64), 1546696 bytes, BuildID 18995cead41f204d5b127934d0ec6651. It was built from Rust sources and has no .comment section.
- **ks2-deps** (verified): keystore2 has 14 NEEDED entries. Of these, libkm_compat_service.so and libsqlite.so are outside this group.
- **ks2-config** (observed): keystore2 uses system properties keystore.boot_level and keystore.crash_count and the data directory /data/misc/keystore. Its init service passes that directory as its first argument, and init.rc sets the boot-level property during boot.
- **ks2-selinux** (verified): keystore2 is labelled keystore_exec. Its data directory is keystore_data_file, its AIDL service name maps to keystore_service, and the keystore2 key contexts are in plat_keystore2_key_contexts.
- **ks2-source** (observed): keystore2 was built from 29 Rust source files under system/security/keystore2/src, including keystore2_main.rs, service.rs, database.rs, super_key.rs, legacy_blob.rs and remote_provisioning.rs, with Rust 1.55.0 standard-library paths.
- **libcrypto64-format** (verified): lib64/libcrypto.so is BoringSSL, built from external/boringssl. It exports about 2386 defined dynamic symbols and depends only on libc, libm and libdl. The 32-bit system/lib/libcrypto.so has the same BoringSSL markers and 2388 exports.
- **set-verity-format-cfg** (observed): set-verity-state is a stripped AArch64 PIE that enables or disables verity. It is invoked either directly with a usage of [1|0] or through the enable-verity and disable-verity names, and it reads and writes the avb.managed_verity_mode property. It depends on libfec, libfs_mgr_binder and libcrypto_utils.
- **fsverity-cert** (verified): fsverity-release.x509.der is a DER X.509 v3 self-signed CA certificate with subject and issuer CN=Android (O=Google Inc., OU=Android), RSA 4096-bit key, public exponent 65537, valid 2020-03-20 to 2050-03-20, and SHA-256 fingerprint 9F:97:31:5D:A5:EC:FF:D9:5B:78:C1:EE:B2:1D:3B:3C:27:1B:C3:0D:AB:61:C0:FA:74:2C:89:E6:20:BE:AC:7D.
- **libfsverity** (verified): libfsverity.so is the fs-verity userspace library. It exports libfsverity_enable, libfsverity_enable_with_sig, libfsverity_sign_digest, libfsverity_compute_digest and hash helpers, and depends on libcrypto.so. Its only NEEDED consumer in the mounted partitions is /system/bin/odsign, which is outside this group.
- **gatekeeperd** (observed): gatekeeperd is a stripped AArch64 PIE daemon that exposes android.service.gatekeeper.IGateKeeperService over binder. It depends on the gatekeeper HIDL 1.0 interface and libgatekeeper, and is started by init at late_start.
- **libgatekeeper64** (verified): lib64/libgatekeeper.so is the gatekeeper core library. It exports GateKeeper::Enroll, GateKeeper::Verify, GateKeeper::MintAuthToken, CreatePasswordHandle, ThrottleRequest and IncrementFailureRecord, and the request and response serialization classes. The 32-bit system/lib/libgatekeeper.so exports 46 gatekeeper:: symbols.
- **keystore-cli** (observed): keystore_cli_v2 is a stripped AArch64 client for keystore2 that exposes the commands confirmation, decrypt, delete, encrypt, generate, get-chars, list, list-brillo-tests, sign-verify and brillo-platform-test. It depends on libchrome, libprotobuf-cpp-lite and libkeymint_support, and its source is system/security/keystore/keystore_cli_v2.cpp.
- **wait-for-keymaster** (observed): wait_for_keymaster is a boot-time helper, run as root with priority -20 by init. It waits for the keystore2 IKeystoreService/default instance and the keymaster maintenance service, and its source is system/vold/wait_for_keymaster.cpp. It is labelled wait_for_keymaster_exec.
- **libkeymaster-portable** (verified): libkeymaster_portable.so is the portable software keymaster implementation. It exports the AndroidKeymaster class, operation classes for RSA, symmetric keys and upgrade messages, and the ae_* authenticated-encryption helpers. It depends on libcrypto, libcppbor_external and libcppcose_rkp.
- **vendor-keymaster41-hidl** (verified): The vendor lib64/android.hardware.keymaster@4.1.so is the HIDL IKeymasterDevice 4.1 interface library. It exports V4_1::IKeymasterDevice with its Bp and Bn proxy and stub classes, and it is published in the vendor VINTF manifest as @4.1::IKeymasterDevice/default.
- **vendor-keymaster41-service** (observed): bin/hw/android.hardware.keymaster@4.1-service-qti is the Qualcomm keymaster 4.1 HAL service. It is started by init as vendor.keymaster-4-1 in the early_hal class, links libqtikeymaster4 and the 4.0 and 4.1 HIDL libraries, and its source is the vendor securemsm keymaster/4.1/service.cpp.
- **qseecomd** (observed): qseecomd is the QSEECom daemon for the vendor TEE path. It runs as root in the core class, owns a notify-topology socket for the drmrpc group, opens /dev/smcinvoke and links libQSEEComAPI, libdrmfs, libminkdescriptor and libdmabufheap. It is labelled tee_exec, and the /dev/qseecom node is labelled tee_device.
- **libqtikeymaster4** (observed): lib64/libqtikeymaster4.so is the Qualcomm keymaster 4.x backend that the vendor keymaster 4.1 service links. It depends on the vendor keymaster device and utility libraries, libqcbor, and the 4.0 and 4.1 HIDL interfaces. It exports 239 defined symbols, including a CR* family of getter functions.

## Claims with corrected wording

These claims held in substance. The wording below replaces the original.

- **ks2-interfaces** (observed): keystore2's binary strings contain the android.system.keystore2 service names (IKeystoreService/default, IKeystoreOperation) and the maintenance, metrics, authorization, compat, APC, legacy keystore and remote provisioning interface names, plus the KeyMint, secure clock and shared secret HAL interface names. It imports AServiceManager_addService and logs 'Successfully registered Keystore 2.0 service.' next to the IKeystoreService/default, APC, authorization, metrics, remote provisioning, maintenance and legacy keystore names. Whether each listed interface is served by the binary or only referenced is not determined from strings.
- **set-verity-refs** (verified): Four binaries in the mounted partitions contain the verity-state command names: system_a/system/bin/init, snapshotctl, update_engine and set-verity-state itself (three besides set-verity-state). The verity-state rows (set-verity-state, enable-verity, disable-verity) and the tee symlink rows are not named in any init.rc or file_contexts entry in the checked partitions.
- **fsverity-init** (observed): fsverity_init is a stripped AArch64 PIE that loads verified fs-verity keys from /system/etc/security/fsverity and /product/etc/security/fsverity (.der files), loads extra keys by name, and locks the .fs-verity keyring. init.rc runs it with --load-verified-keys in the 'on late-fs' block (line 647) and with --lock in the 'on post-fs-data' block (line 981).
- **gatekeeperserver** (verified): gatekeeperserver is a small OVR gatekeeper service host. It imports GatekeeperNativeService::createProdInstance and ServiceHost and is started by init in the main class. It links libgatekeepernativeservice.so, whose strings contain /data/oculus/gatekeepers/gks.db. That library exports override and clear methods (overrideGatekeeper, clearOverrideGatekeeper, clearOverriddenGatekeepers, clearGatekeeper) and a dump entry point.

## Gaps

- Stripped binaries (keystore2, gatekeeperd, gatekeeperserver, fsverity_init, set-verity-state, wait_for_keymaster, keystore_cli_v2, qseecomd, both HAL service processes): function-level behaviour, internal state layouts and on-disk database formats were not determined. Descriptions rely on exported and imported symbols, NEEDED entries, strings and init/SELinux text.
- Dependencies outside this group that were not analysed: libkm_compat_service.so and libsqlite.so (NEEDED by keystore2), libkeyutils.so, libselinux.so, libfs_mgr_binder.so, libfec.so, libQSEEComAPI.so, libqcbor.so, libcppbor_external.so, libcppcose_rkp.so, libkeymint_support.so, libchrome.so, libprotobuf-cpp-lite.so, libgsi.so, libkvstore.so, libosutils.so.
- The KeyMint service binary (vendor_a/bin/hw/android.hardware.security.keymint-service-qti, with its init rc and vintf manifest, which are in vendor_a) is referenced by the group's VINTF and SELinux files but is not in this group, so it was not analysed.
- The consumer of libkm_compat_service.so is keystore2 by NEEDED entry, but the implementation of that library is outside the group and was not examined.
- odsign (system_a/system/bin/odsign, NEEDED libfsverity.so) is outside this group. Its use of libfsverity was checked only by its NEEDED entry.
- No explicit file_contexts entries were found for set-verity-state, enable-verity, disable-verity, tee, keystore_cli_v2 or the group's shared libraries. The default labelling rule that applies to them was not determined.
- The runtime key-loading path of fsverity_init (which key files it actually loads at boot) and the fs-verity sign-and-verify flow were not reproduced. The release certificate's role is inferred from the file name and the search path strings.
- The 32-bit and 64-bit gatekeeper core libraries, the 32-bit vendor gatekeeper implementation (vendor_a/lib/hw/android.hardware.gatekeeper@1.0-impl-qti.so), the 32-bit vendor keymasterdeviceutils library, the vendor copies of libkeymaster4support and libkeymaster_messages, and the vendor 3.0 and 4.0 HIDL libraries were identified from names, NEEDED lists and sizes, not from symbol-level inspection. The vendor copies of libkeymaster4support and libkeymaster_messages have the same size as their system counterparts but different sha256 values, and the reason was not determined.
- The meaning of the CR* getter family in libqtikeymaster4 and the vendor.gatekeeper.disable_spu key in the gatekeeper implementation was not determined. The vendor.wv.oemcrypto.debug.* keys in liboemcrypto were listed only, not interpreted.
- The vendor boringssl_self_test init rc (vendor_a/etc/init/boringssl_self_test.rc) and its relation to libcrypto were not examined.
- SELinux sources are compiled CIL only (no .te files). Domain transitions for keystore2 and gatekeeperd were not traced end to end; only exec labels and type declarations were confirmed.
- The toybox applets behind the tee symlinks were not examined.
