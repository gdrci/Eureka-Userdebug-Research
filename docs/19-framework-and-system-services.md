# 19 - Framework and system services

[中文版](19-framework-and-system-services.zh-CN.md)

## Summary

The group has 707 rows: 229 symlinks and 478 regular files, spread across system_a (681), system_ext_a (15), product_a (9) and odm_a (2). It holds the framework layer: bytecode and ART artifacts (services.jar, framework.jar, framework-res.apk, the services.odex/.vdex/.art set, the arm and arm64 boot-framework images), the native daemons and command clients in system/bin (servicemanager, hwservicemanager, app_process32/64 zygote launchers, toybox and toolbox applet links, cmd, service, and about 180 others), 22 APEX module packages, about 33 shell wrapper scripts that exec app_process or cmd, and XML configuration (platform.xml, privapp-permissions, default-permissions, framework-sysconfig, hidden-API whitelist, feature and library declarations). Startup wiring is visible in the init rc files (zygote variants, servicemanager, hwservicemanager) and in plat_file_contexts entries for the binaries. Neither the init nor the SELinux files in the mounted system_a tree name any of the XML configuration files. All roles and facts are read from the mounted copy; nothing was executed.

The role table has one row for each of the 707 files in this group (324 verified, 281 observed, 101 inferred, 1 unverified). It is at `data/subsystems/framework-and-system-services/roles.tsv`.

## Gaps

- Purpose of the five .uau members inside services.jar was not determined; their format was not decoded.
- Binary XML AndroidManifest.xml inside framework-res.apk and the APK-type packages was not decoded; package names of the APK-type jars were not extracted.
- Dex code of services.jar and framework.jar was not disassembled; only the dex version and selected string-table entries were read, so the set of services started by SystemServer was not enumerated.
- The ART OAT key-value header, method tables and checksums inside services.odex and boot-framework.oat were not parsed; the boot-framework.art image header fields were not decoded.
- APEX payload filesystems (ext4) were not mounted or listed; only their manifest names and magic values were read.
- Roles for the Meta- or Oculus-specific ELF executables and for hw/android.hidl.allocator@1.0-service and android.system.suspend@1.0-service are name-based. Nothing was executed, because the binaries are ARM images.
- The toybox applet list was not enumerated; the 173 toybox symlink names are given only by their readlink targets.
- Binder interfaces exported by cmd and service were not enumerated beyond their usage and error strings; no AIDL descriptor list was extracted for servicemanager.
- Init and SELinux searches covered only the system_a/system/etc/init and system_a/system/etc/selinux directories. vendor_a, odm_a, product_a and system_ext_a init and SELinux files were not searched, so references from those partitions are unknown.
- Whether platform code loads platform.xml, privapp-permissions-platform.xml, framework-sysconfig.xml, default-permissions.xml or hiddenapi-package-whitelist.xml at runtime was not verified; no file in the mounted init or SELinux trees names them.
- The eight symlinks listed in C06 that sit outside this group were not classified here.
- preinstalled-packages-com.android.providers.media.module.xml has no XML declaration and was read only as text; no structured parse was done.
- The services.odex and boot-framework.oat DT_NEEDED lists were not extracted, since the files are ELF containers around ART code and the runtime dependencies are recorded in the OAT header instead.
