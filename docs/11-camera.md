# 11 - Camera

[中文版](11-camera.zh-CN.md)

## Summary

The camera group has 83 files in five partitions (vendor_a 57, system_a 12, system_ext_a 6, odm_a 4, product_a 4). Its core is a QTI Camera HAL3 module (vendor_a/lib64/hw/camera.qcom.so, hw_module id "camera", module API 3.0) that loads CHI pipeline and 3A/statistics component libraries from vendor_a/lib64/camera/components; an XR camera HAL implementation (vendor_a/lib64/libxrcamerahal.so) is reached through an odm shim (odm_a/lib64/libcamerahal.so exporting CameraHalC_Init/Start/Stop/Deinit). A camera mux-mode service family (system_ext cameramuxmodeservice daemon, a client monitor library, a JSON reader library and a command-line client) is configured by /product/etc/cameramuxmode/config.json (v1) and by configv2.json (version 3), which is duplicated in vendor_a and read by the odm sensor service. The CAMERA_ICP firmware is an Xtensa ELF32 MDT image with 21 program headers, 13 of whose segment files carry data. vendor_a/etc/camera holds 16 tuning and sensor-module blobs (Chromatix headers, AEC/AWB tables, CVA and depth AE JSON) for IMX471, OG01A1B and OV7251 sensors, and system_a holds framework and HIDL client libraries (camera.common@1.0, camera.device@3.2, camera2 NDK, camera client, camera metadata) in 32-bit and 64-bit builds. Init references in the mounted partitions name only cameramuxmodeservice; SELinux labels cover the mux-mode service, its config directory and properties, and the firmware directory.

The role table has one row for each of the 83 files in this group (38 verified, 43 observed, 2 inferred, 0 unverified). It is at `data/subsystems/camera/roles.tsv`.

## Verified claims

- **C01** (verified): The camera group contains 83 rows: vendor_a 57, system_a 12, system_ext_a 6, odm_a 4, product_a 4. Mounted files live under B/mnt, where B is <image>. Commands in later claims are run from B/mnt unless a path is absolute.
- **C02** (verified): Every one of the 83 rows exists under B/mnt, and its byte size and sha256 equal the recorded values.
- **C03** (verified): Three groups of rows have identical content: product_a and vendor_a etc/cameramuxmode/configv2.json; vendor_a etc/camera cvaectuning_ht.json and cvaectuning_slam.json; and eight zero-byte firmware segments.
- **C05** (verified): The HAL module symbol HMI decodes as a hw_module_t with tag 0x48574d54, module_api_version 0x0300, hal_api_version 0x0100, id camera, name QTI Camera HAL, author Qualcomm Technologies, Inc. Its methods pointer is 0xa36fa0.
- **C06** (verified): camera.qcom.so has 39 NEEDED entries. They include the CamX core libraries (libcamxcommonutils, libcamxhalbuffermanager, libcamxsettingsmanager, libcamxcsl, libcamxfdengine, libcamxhwnodecontext, libcamximageformatutils, libcamxstatscore), gralloc and display HIDL libraries, the QMI and sensor-calibration libraries, and libcamera_metadata.

- **C45** (verified): Program header index N maps to segment file CAMERA_ICP.bNN, and the file size equals the program header FileSiz in all 21 cases. Thirteen segment files carry data (b00 to b09, b17, b18, b20). Eight are zero bytes (b10 to b16 and b19). Its C-linkage exports are CameraHalC_Init, CameraHalC_Start, CameraHalC_Stop and CameraHalC_Deinit; it also exports 14 mangled C++ symbols in the CameraHal namespace. It NEEDs libbase, libimagebuffer, liblog, libmros_vendor_sysprops, libsensortelemetry, libui and libutils (plus libc++, libc, libm and libdl).

Its candidate names include libfastpathcamerahal.so and an xrcamera-named library (libxrcamerahal.so). Its properties are persist.vendor.camera.hal and vendor.camera.hal.debug_file.
- **C17** (observed): syncboss_camera_tests is a stripped AArch64 shared-object-type executable with interpreter /system/bin/linker64. It is a test binary for the SyncBoss camera path (inferred from its name and log text), carries SyncBoss log text, and contains the string libcamerahal.so, which is not among its NEEDED entries (liblog.so, libm.so, libdl.so, libc.so).
- **C23** (verified): libcameramuxmodemonitor.so (lib64) is a 115,544-byte AArch64 shared object with 168 defined and 194 undefined named dynamic symbols (195 undefined entries if the null entry at index 0 is counted). It exports CameraMuxModeMonitor and the ICameraMuxModeClient and ICameraMuxModeService binder interface symbols. It NEEDs 13 libraries, including libvrsensors-hidlwrapper.so and libvrsensors-utils.so.

No SELinux file-context entry covers /vendor/etc/cameramuxmode.
- **C40** (verified): The six com.qti.sensormodule.camNN bins are named com.qti.sensormodule.camNN_<token>_eureka_<sensor>_<side>_csiN.bin (verified tokens): cam00 none og01a1b left csi4; cam01 none og01a1b right csi1; cam02 liteon ov7251 left csi5; cam03 liteon ov7251 right csi2; cam04 none imx471 left csi0; cam05 none imx471 right csi3. The meaning of the second token (module vendor, with none meaning no module vendor) is inferred.
- **C41** (observed): camera.qcom.so names a sample sensor-module file com.qti.sensormodule.truly_ov8856.bin and its two-lane variant, which show the short com.qti.sensormodule.<sensor>.bin naming. The six bins in this group use the longer com.qti.sensormodule.camNN_<vendor>_eureka_<sensor>_<side>_csiN.bin form (see C40). No literal match for the group's file names, or for the tokens eureka, cam04, imx471, og01a1b or ov7251, appears in camera.qcom.so.

## Gaps

- The camera provider service binary (the android.hardware.camera.provider@2.x-service that loads camera.qcom.so) is not among the mounted partitions searched, so its NEEDED list, its registration and its init rc are undetermined.
- No init rc in the mounted init directories starts the QTI camera HAL, cameratool, libcamerahal, the postproc HIDL service or a firmware loader for CAMERA_ICP; these starts are unresolved.
- No vintf manifest entry for android.hardware.camera.provider or vendor.qti.hardware.camera.postproc was found in the mounted vintf directories; only the system compatibility matrices were located.
- The CAMERA_ICP loader is not identified. camera.ko names CAMERA_ICP.elf while the set holds CAMERA_ICP.mdt and the segment files. The load order, the segment-type semantics of the program header flags, and any verification flow were not determined, and no assessment was made.
- The meaning of the ICP firmware segment payloads (code and data layout, command formats and the sign-off text in segment 20) is limited to text labels and headers; no disassembly was performed.
- The Chromatix tuned and sensor-module blobs were decoded only at the header, size and checksum level. Parameter sections and their values were not parsed.
- The AEC and AWB core tuning tables (binary, no header magic) were not decoded beyond size, leading bytes and text labels.
- The CHI pipeline graph definitions (XML or JSON describing com.meta.node.* and com.qti.* nodes) are not in this group; the node topology is unresolved.
- The odm libcamerahal shim's selection between the XR HAL and a fastpath HAL is not resolved, because libfastpathcamerahal.so is absent from the mounted partitions.
- The field-level parser for configv2.json was not located. libcameramuxmodereader.so exports only a file-content getter, and cameramuxmodeservice reads only the v1 path literal. Which binary parses the v3 keys (version, cameraSystems, modes) is unresolved.
- The system_a 32-bit libraries (lib/ directory) were sampled by SONAME, NEEDED and export names only, and their roles rest on those names.
- Roles for camera_click.ogg and camera_focus.ogg are inferred from file names alone.
- cameratool and syncboss_camera_tests were not executed; their behaviour is described from option and log text.
- The dependency closure was checked only for the libraries named in this review. Libraries from other partitions such as libsyncboss.so, libdevicesensors.so and libcamxcsl.so were confirmed present, but the full NEEDED resolution for every row was not computed.
- vendor_dlkm_a and odm_dlkm_a were searched only for the camera.ko string; their other contents are outside this group.
