# 08 - HAL manifests (VINTF)

[中文版](08-hal-manifests.zh-CN.md)

## Summary

The hal-manifests group is 62 VINTF XML files, all of them the only etc/vintf files on the mounted partitions: vendor_a 20, odm_a 18, system_ext_a 12, system_a 11, product_a 1. None is a binary, library or firmware image. The files declare HAL package, version, transport and instance for the framework (system_a manifest.xml, level-based compatibility matrices 3 to 6 and a device matrix), system_ext, vendor and odm layers. Most declared HALs are also named in init service entries and in the SELinux hwservice_contexts or service_contexts files. A name-level cross-reference matched 414 manifest and matrix entries to context files; 7 matrix requirement names had no context entry. Two device-matrix requirements (vendor.oculus.hardware.mixedreality and vendor.oculus.hardware.peripheralconfig@1.0, both optional) have no provider among the 62 files. For two odm HALs (sensors and usb) the init rc or the hwservice context declares more interfaces or versions than the manifest fragment does.

Role table: `data/subsystems/hal-manifests/roles.tsv` (62 files: 59 verified, 0 observed, 3 inferred, 0 unverified).

## Verified claims

- **GRP-01** (verified): The group has 62 rows, and these are exactly the 62 etc/vintf files present on the mounted partitions. Per partition: vendor_a 20, odm_a 18, system_ext_a 12, system_a 11, product_a 1. No other partition (odm_dlkm_a, vendor_dlkm_a, scratch) has a vintf file.
- **GRP-02** (verified): All 62 files match the sha256 values recorded in classified.tsv and all 62 are well-formed XML.
- **GRP-03** (verified): Across the 62 files: 56 have a manifest root and 6 have a compatibility-matrix root. HAL format attributes: hidl 309, aidl 61, native 1, unset 14. Transports: hwbinder 57, passthrough arch=32+64 5. optional attribute on hal: true 268, false 38, unset 79. override attribute on hal: 2.
- **GRP-05** (verified): Framework manifest system_a/system/etc/vintf/manifest.xml is version 4.0, type framework, with 9 HAL declarations and system-sdk versions 28 to 32. It declares android.frameworks.displayservice IDisplayService, android.frameworks.schedulerservice ISchedulingPolicyService (max-level 5), android.frameworks.sensorservice ISensorManager, android.hidl.manager IServiceManager@1.2, android.hidl.memory IMapper (passthrough, arch 32+64, instance ashmem), android.hidl.token ITokenManager, android.system.net.netd INetd@1.1, android.system.wifi.keystore IKeystore, and a native netutils-wrapper@1.0 entry.
- **GRP-07** (verified): Framework compatibility matrices for levels 3, 4, 5 and 6 have 57, 61, 66 and 78 HAL requirement entries. Each carries kernel requirement lines for its level, for example level 6 requires 4.19.191 (8 entries), 5.4.86 (9) and 5.10.43 (9). Their header comments name matrix_kernel_config_*.xml inputs, and none of those files exist on the mount.
- **GRP-08** (verified): Device manifest vendor_a/etc/vintf/manifest.xml is version 4.0, type device, target-level 4. It has 8 HAL declarations (among them android.hardware.bluetooth IBluetoothHci, android.hardware.keymaster @4.1 IKeymasterDevice, android.hardware.media.omx IOmx and IOmxStore, vendor.qti.hardware.qseecom IQSEECom). It has a sepolicy version 32.0 and a kernel target-level 6. The platform sepolicy version file reads 32.0.
- **GRP-09** (verified): Device compatibility matrix vendor_a/etc/vintf/compatibility_matrix.xml is version 4.0, type device. It lists 6 framework HAL requirements (android.frameworks.sensorservice ISensorManager, android.hidl.allocator IAllocator, android.hidl.manager IServiceManager, android.hidl.memory IMapper, android.hidl.token ITokenManager, android.system.wifi.keystore IKeystore), vendor-ndk 32 and system-sdk 32.
- **GRP-10** (verified): system_ext_a/etc/vintf/manifest.xml declares no HAL. Its only content is a vendor-ndk entry with version 32, and it carries an XML comment naming system_ext_manifest.default.xml as input.
- **GRP-12** (verified): android.hardware.security.keymint-service-qti.xml declares four AIDL entries under package android.hardware.security.keymint and sharedsecret/secureclock: IKeyMintDevice/default, ISharedSecret/default, ISecureClock/default and IRemotelyProvisionedComponent/default. The matching SELinux service_contexts entries are in plat_service_contexts lines 16 to 19. The init service vendor.keymint-qti runs /vendor/bin/hw/android.hardware.security.keymint-service-qti (class early_hal, 36656 bytes on the mount).
- **GRP-13** (verified): android.hardware.light@2.0-service.anorak.xml declares android.hardware.light@2.0 ILight and vendor.oculus.hardware.light@2.0 ILight, both hidl over hwbinder with instance default. The init service light-hal-2-0 registers the same two interfaces and runs /vendor/bin/hw/android.hardware.light@2.0-service.anorak (101480 bytes). SELinux maps vendor.oculus.hardware.light::ILight to hal_light_hwservice. The AIDL name android.hardware.light.ILights/default appears in plat_service_contexts but is not declared by any group manifest.
- **GRP-15** (verified): odm android.hardware.usb@1.2-service.xml declares IUsb 1.2 and IUsbGadget 1.2. The odm init service vendor.usb-hal-1-2 registers IUsb 1.0, 1.1 and 1.2 and IUsbGadget 1.0, 1.1 and 1.2 for /odm/bin/hw/android.hardware.usb@1.2-service.ovr (193360 bytes). So the init entry lists older interface versions than the manifest. The SELinux hwservice context has android.hardware.usb::IUsb and android.hardware.usb.gadget::IUsbGadget. The manifest file name omits the .ovr suffix that the binary carries.
- **GRP-16** (verified): odm perfservice.xml declares IPower 1.3 (android.hardware.power), IThermal 1.0 and 2.0 (android.hardware.thermal), and IClocks 1.0 (vendor.oculus.hardware.clocks), all hwbinder with instance default. The odm perfservice.rc starts /odm/bin/hw/perf_service (501832 bytes) and registers IPower 1.0 through 1.3, IThermal 1.0 and 2.0, and IClocks 1.0. Its restart is keyed to init.svc.zygote=restarting. Its hwservice labels are in plat_hwservice_contexts (power and thermal) and system_ext_hwservice_contexts (clocks).
- **GRP-17** (verified): system_ext tracking_manifest.xml declares four optional AIDL HALs under name oculus.internal.tracking: IFaceEyeTrackingService, IHandTrackingService, IInsideOutBodyTrackingService and IMemoryBrokerService, each instance default. The system_ext service_contexts file lists seven oculus.internal.tracking entries (lines 60 to 66), including IEyeTrackingService and ITrackingService, which this manifest does not declare. Line 60 is IAssetReceiver/encoder.
- **GRP-20** (verified): Only two HAL entries in the group carry override=true. Both are in system_ext: vendor.oculus.hardware.composer-service.xml overrides android.hardware.graphics.composer 2.4 IComposer for instance display, and emgservice_manifest.xml (manifest version 2.0) overrides com.meta.wearable.emg IEmgService/default (AIDL, optional).
- **GRP-21** (verified): Two framework fragments in system_a have matching SELinux labels. android.frameworks.stats@1.0 IStats has max-level 5 and an aidl IStats/default entry; plat_hwservice_contexts maps android.frameworks.stats::IStats to fwk_stats_hwservice and plat_service_contexts maps android.frameworks.stats.IStats/default to fwk_stats_service. android.system.keystore2-service.xml declares AIDL IKeystoreService/default; plat_service_contexts maps it to keystore_service.
- **GRP-22** (verified): The clearkey and widevine DRM manifests are the same file except for the instance name. Both are 945 bytes and declare android.hardware.drm with IDrmFactory and ICryptoFactory at version 1.4 over hwbinder. Only the fqname lines differ.
- **GRP-23** (verified): product_a crashuploaderservice-default.xml declares AIDL meta.internal.diagnostics ICrashUploaderService/default. The name appears in system_ext_service_contexts line 24, and product_a/etc/init/ovr_crashuploader.rc and product_a/bin/ovr_crashuploader exist on the mount. The init rc was not read.
- **GRP-25** (inferred): The vintf directories follow one layout. vendor_a/etc/vintf holds manifest.xml, compatibility_matrix.xml and a manifest/ directory. odm_a/etc/vintf and product_a/etc/vintf each hold only a manifest/ directory. system_ext_a/etc/vintf holds manifest.xml and manifest/. system_a/system/etc/vintf holds manifest.xml, compatibility_matrix.*.xml and manifest/. The framework or device loader is therefore likely to assemble one manifest from each partition's manifest.xml plus its manifest/ fragments.
- **GRP-26** (inferred): The partition-to-path mapping is consistent with the init service paths: odm_a to /odm, vendor_a to /vendor, system_ext_a to /system_ext, system_a/system to /system. Examples are /odm/bin/hw/perf_service, /vendor/bin/hw/android.hardware.light@2.0-service.anorak and /system_ext/bin/bpfagent.

## Claims with corrected wording

- **GRP-04** (observed): Three files are classified text/xml (parfait.xml and the two DRM manifests), and file(1) agrees with that class for all three, reporting XML 1.0 document. Of the 59 text/plain files, file(1) reports exported SGML document for 18 (for example system_a/system/etc/vintf/manifest.xml) and plain ASCII text for 41.
- **GRP-06** (verified): Name-level coverage by the 56 manifest roots (of the 62 files) is 28 of 30 device-matrix names. The two names with no provider are vendor.oculus.hardware.mixedreality (optional true) and vendor.oculus.hardware.peripheralconfig 1.0 (optional true). The full HAL name vendor.oculus.hardware.peripheralconfig occurs only in system_a/system/etc/vintf/compatibility_matrix.device.xml on the mount; the bare token peripheralconfig also appears in 10 other files as library, tool and path names.
- **GRP-11** (verified): The four interfaces have SELinux labels in three context files: vendor_a/etc/selinux/vendor_hwservice_contexts (IQtiComposer at line 9 and vendor.display.config::IDisplayConfig at line 2), vendor_a/etc/selinux/vendor_service_contexts (AIDL vendor.qti.hardware.display.config.IDisplayConfig/default at line 4), and system_a/system/etc/selinux/plat_hwservice_contexts (android.hardware.graphics.composer::IComposer at line 36).
- **GRP-14** (verified): Four odm init rc files start the vendor.oculus.hardware.sensors@1.0 services from /odm/bin/hw: the debug, mock, iad and flicker rc files. A fifth odm rc, vendor.oculus.hardware.sensorlock-service.rc, also starts a service from /odm/bin/hw (an AIDL sensorlock service). The debug service starts on boot when persist.vendor.oculus.sensor.service.impl=sensorservice, and the mock service is disabled. The 18 hwservice entries are at vendor_a/etc/selinux/vendor_hwservice_contexts lines 31 to 48.
- **GRP-18** (verified): bpfagent_manifest.xml declares AIDL vendor.oculus.hardware.bpfagent version 1 with IConfigurator/default and IStrobemeta/default, not marked optional. The system_ext init service bpfagent declares both as aidl interfaces and is disabled at start. SELinux maps the names to bpfagent_configurator_service and bpfagent_strobemeta_service. The CIL policy source file vendor_a/etc/selinux/plat_pub_versioned.cil (text, not a compiled binary policy) defines the hal_bpfagent_* type attributes at lines 666 to 671.
- **GRP-19** (verified): instsampd_manifest.xml declares one optional AIDL HAL, oculus.internal IInstructionSampler/default. The system_ext init service instsampd (/system_ext/bin/instsampd, 396880 bytes) declares the same interface, runs in class late_start, and is disabled at start. Its start, stop and enable triggers are gated on persist.device_config.oculus_shared_os_services.oculus_mobile_instruction_sampler_enabled and ro.vendor.build.type; two other property triggers (ovr.instsampd.kptr_restrict_access and ovr.instsampd.set_perf_event_limits) act on their own properties. SELinux maps the name to instsamp_service.
- **GRP-27** (verified): The compatibility matrices contain hidl (261) and aidl (37) requirements. Of the 298 matrix requirement entries, 260 are optional true and 38 optional false. Across all 385 hal elements in the 62 files, 268 are optional true, 38 false and 79 have no attribute (the last two groups include manifest entries). The framework matrix compatibility_matrix.device.xml has 30 of 30 entries optional true; the device-type matrix vendor_a/etc/vintf/compatibility_matrix.xml has 6 of 6 entries optional false.

## Gaps

- No binaries, libraries or firmware are in the group (all 62 rows are VINTF XML). Binaries named by init were checked only for existence and size, not analysed (no ELF dependency or symbol review).
- HIDL .hal and AIDL interface sources are not on the mount. Method signatures, data types and version compatibility beyond the declared version numbers were not determined.
- Kernel config inputs named in compatibility matrix headers (matrix_kernel_config_*.xml) are absent, so kernel requirement lines could not be matched to a kernel config.
- Name-level coverage counts use only the 62 group manifests. No other manifest exists on the mounted partitions, so vendor.oculus.hardware.mixedreality and vendor.oculus.hardware.peripheralconfig have no provider on the mount. Whether a provider exists on a device image outside the mount is not determined.
- Cross-reference is by name and instance only. hwservice_contexts entries carry no version, so version-level matching against the declared versions was not performed.
- The SELinux policy compiled files (plat_pub_versioned.cil, vendor_sepolicy.cil) were searched for name matches only. Domain allow rules for each HAL were not analysed.
- The init rc files for the vendor, system and product HAL services were read only where they name a group HAL. Services not tied to a group HAL, such as ovr_crashuploader.rc, were not read.
- Version mismatches between init interface lines and manifests were recorded for usb (init lists 1.0 to 1.2, manifest 1.2 only) and perfservice (init lists IPower 1.0 to 1.3, manifest 1.3 only). Whether these mismatches affect runtime behaviour was not tested.
- The sensors context file lists 18 interfaces for the vendor.oculus.hardware.sensors package, the odm manifest 10. The runtime registry contents were not observed, so it is not known which interfaces the sensor service actually registers.
- Runtime behaviour (service start, registration with hwservicemanager or servicemanager, VINTF check at boot) was not observed. All statements about it are from file content only.
- file(1) labels for these XML files are inconsistent (XML document versus exported SGML document). The file-type labels were not used as evidence beyond recording that inconsistency.
